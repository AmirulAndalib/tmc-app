# Gotchas

Traps that do not error usefully, grouped by where they bite. The ones that belong to one subsystem are in that subsystem's file instead (deployment in [sandboxes.md](sandboxes.md), downloads in [downloads.md](downloads.md), launcher manifests in [detection.md](detection.md), launch arguments in [playing.md](playing.md), and so on). How several of these were found is in [history.md](history.md).

## Contract, query strings and the browse screen

- **A query string carries no types, so `parseQuery` does not guess.** Values arrive as strings and the contract coerces per field (`z.coerce.number()`, `QueryBool`). Guessing from shape breaks `?search=2024`, `?search=true` and — because every cursor is a numeric id — the second page of every listing.
- **`z.coerce.boolean()` is `Boolean(value)`**, so the string `"false"` is `true`. Use `QueryBool` from the contract.
- **A query-string field that is sometimes a list must be in the site's `ARRAY_FIELDS`** (website-city `src/lib/app-api/handler.ts`). `?ids=42` and `?ids=42&ids=43` otherwise reach the schema as different SHAPES, so the one-element case fails validation while the two-element case passes — invisible in any test that happens to use two values.
- **Every browse filter lives in the URL, never in component state.** A filtered browse has to survive a reload, a deep link and the back button, and a HashRouter over a static bundle has nowhere else durable to put it. `lib/api/query-params.ts` is the only place that encoding is decoded (and its inverse); `browse.tsx`'s `param`/`flag`/`num`/`idList` read through it. Multi-selects are comma lists.
- **`sort=players` is a deprecated alias of `curUsers`.** The app invented the name; the website has always called it `curUsers`. It stays in the contract's enum because an installed build is not redeployed with the server and would otherwise 400 on every server browse — but it is never offered in the sort dropdown.
- **The server browser defaults to the table, every other kind to the grid.** `?view=grid` / `?view=table` overrides it, and `view` is only honoured for `kind === 'server'` — nothing else has a table to switch to.
- **The server browser's defaults are the website's** (`lib/user/settings/default.ts` there): sort by player count descending, online only, table view. Sorting servers by "newest" lists millions of freshly imported rows that were never once seen online, and every one reads `TO`.
- **Ping is the FIRST column in the table**, as it is on the website. The table is wider than its pane and scrolls horizontally, and the one column the app exists to provide must never be the one that disappears.
- **A live `maxPlayers` is only believed when `>=` the live player count.** Several games report A2S `max_players` as something other than capacity (one answers ignoring its queue, which rendered as `144/51`). The measured PLAYER count always wins; only the slot count falls back to the API's.
- **An app ref carries the game's FULL name, never `App.nameShort`.** The site abbreviates because its chrome is built around one chosen game; here a `nameShort` that is unset — or `''`, which `??` happily returns — is a blank, selectable row in the game picker. website-city's `mapApp` (`lib/app-api/content.ts`) and the `/facets` handler send `App.name`, and `lib/api/labels.ts`'s `appLabel` is the display-side guard. Use it wherever a game is named on screen.
- **Articles are opened in the system browser, not rendered.** `lib/external.ts` holds the list. Their bodies are laid out for the website's content column, and the app's markdown subset strips exactly the parts carrying that layout.
- **The offline cache is an ALLOW-list, and it restores the original timestamps.** `lib/api/offline-cache.ts` stores `browse`, `content`, `facets` and `reviews` — public catalogue data — in `localStorage` and puts them back at boot with their old `dataUpdatedAt`; restoring them as fresh would suppress the refetch. An allow-list because the failures are not symmetrical: a forgotten account query on a deny-list is written to disk in cleartext, a forgotten public one on an allow-list costs a spinner. `me`, `log` and `plugins` are excluded by not being on it.
- **The live-query context's accessors are stable; `version` is the render signal.** Putting a context accessor in an effect dependency list re-runs that effect on its own result — for the server panel, an unbounded query loop against a real game server.

## TypeScript, CSS and the build

- **`typescript` is held at ~6.0 only for typescript-eslint; the type-check is TypeScript 7.** TS 7 is the native compiler with no JS API, and typescript-eslint's peer range stops below 6.1, so eslint loads `typescript` (6.0) while `npm run typecheck` runs the `typescript7` alias. Drop the 6.0 pin once typescript-eslint supports TS 7.
- **React Compiler lint (react-hooks 7) is conservative:** it flags any state-setting function called from an effect body, even after an `await`, and a hook result holding a `ref` property passed to `ref=` taints the whole object. Fixes used: callback ref stored in state, state tagged with its key and derived, render-time "seen" adjust, and `queueMicrotask` to start load-on-mount work.
- **A `const` in `schemas.ts` referenced before its initializer runs is a runtime TDZ error, not a type error.** `tsc` accepts it and the app throws on module load with a message about the wrong file. New schemas go BELOW everything they reference.
- **Tailwind 4 generates a utility only for a token that EXISTS.** A misspelt token produces no class and no error, which looks exactly like a design choice. `app.css`'s `@theme inline` block aliases `--color-surface-2` to the shared theme's `--surface-secondary`; before inventing a colour name, check `@modcommunity/shared`'s `src/styles/theme.css`.
- **Unlayered CSS in `app.css` beats Tailwind's `@layer utilities`**, whatever the specificity — the cascade's layer rule. Resets in that file must be properties no utility sets.
- **`@source` in `app.css` is required.** Tailwind ignores `node_modules`, so without it the shared components' classes are never generated.
- **A native `<select>`'s popup is drawn by the OS and cannot be styled.** `components/select.tsx` is a real listbox and every `<select>` in the app is gone; adding one back brings a white rectangle into every dark-themed pane.
- **Brand marks come from `react-icons/fa6`, never lucide.** lucide dropped its brand glyphs. lucide stays the house icon set for everything else.
- **Vite 8 minifies with oxc.** Setting `minify: 'esbuild'` demands esbuild as a separate install.
- **`openUrl` cannot open a `steam://` link, and fails silently.** `tauri-plugin-opener` is scoped to `https://*` deliberately, so the webview cannot open a scheme something else registered. Anything that is not `https` goes through Rust, where the scheme is checked against `plugins::apps::LAUNCH_SCHEMES`.

## Rust and Tauri

- **`serde(rename_all = "SCREAMING_SNAKE_CASE")` turns `A2S` into `A2_S`.** It splits between a digit and the next letter. `QueryProtocol::A2S` carries an explicit `#[serde(rename = "A2S")]`, and `every_protocol_round_trips_under_its_wire_name` checks every variant against a hardcoded `WIRE_NAMES` list. Reading the enum will not catch it: the variant names look identical to the wire names. One bad row fails a whole `Vec<QueryRequest>` batch.
- **`serde(rename_all)` does not rename variant fields.** Enum variants in the plugin manifest need `rename_all_fields = "camelCase"` too, or a manifest would have to write `max_bytes`.
- **`Path::join` with an absolute argument discards the base.** That is why `join_relative` exists and why nothing in the plugin path calls `join` on untrusted input.
- **`std::fs::canonicalize` on Windows returns `\\?\F:\Games`, not `F:\Games`.** A verbatim path is one where `.` and `..` mean nothing and `/` is not a separator, several launchers refuse one, and `\\?\F:\Games` vs `F:\Games` are one directory and two strings, so a `starts_with` between a resolved and a joined path answers "outside" for everything. `tmc_core::canon::canonicalize` is the only way this tree resolves a path; `strip_verbatim` is pure string work (tested on every platform) and declines the four cases where the prefix is load-bearing (a volume GUID, a path past `MAX_PATH`, a component Win32 would rewrite, a device name).
- **`tokio::spawn` inside a function the spawned task calls back into is an infinitely large future type.** The download queue's `pump` → `run_one` → `pump` cycle is broken with one boxed future (`pump_boxed`); without it the compiler says "cannot satisfy `impl Future: Send`", which does not obviously mean "you wrote a recursive future".
- **`generate_handler!` needs full module paths.** `commands::auth::auth_begin`, not a `pub use` of it — the macro also needs the hidden `__cmd__*` items `#[tauri::command]` generates, and those do not travel through a re-export.
- **`tauri.conf.json`'s feature allowlist and `Cargo.toml`'s `tauri` features must agree**, or the build script refuses with a message about `protocol-asset`. The asset protocol is deliberately off in both.
- **`keyring` is behind a feature.** It talks to the Linux Secret Service (zbus since keyring 4; the default `v1` feature keeps the 3.x API) and touches the user's real keychain. It is behind `tmc-core`'s `os-keyring` feature, off by default and enabled by the app crate — which is why `npm run test:core` works on a bare machine.
- **A `///` block followed by a blank line documents the NEXT item.** Module headers are `//!` at the top of the file; clippy's `empty_line_after_doc_comments` catches the mistake under `check:rust`'s `-D warnings`.
- **A tRPC mutation cannot set a cookie on a streamed response.** Relevant when touching the website's device-approval router — see website-city's `src/trpc/react.tsx`.
- **`cargo update` can pick a crate release a Tauri plugin does not compile against yet (`rust-ini` 0.21.3 vs `tauri-plugin-deep-link` 2.6.2)**: hold it with `cargo update -p <crate> --precise <ver>`, and `zip` 9 needs `FileOptions<'_, '_, ()>` in tests.

## Workflows

- **No apostrophe inside `${VAR:-...}` in a workflow `run:` block.** Within double quotes bash reads it as an opening quote and the whole step dies with "unexpected EOF while looking for matching": the release's Build step failed on every platform for that reason until 0.2.0. A release tag is the only thing that runs `release.yml`, so check its blocks with `bash -n` before tagging.
- **A play window builder call may be desktop-only.** Tauri declares `center`, `inner_size`, `decorations`, `fullscreen` and the rest of the sizing calls under `cfg(desktop)`; ungated, the Android build does not compile. `cargo check -p tmc-app --target aarch64-linux-android` needs an NDK's clang as `CC_aarch64_linux_android` (ring builds C).

## Versions

- **Version comparison is numeric per component, and refuses what it cannot order.** `1.10.0` sorts BEFORE `1.9.0` as a string. `tmc_core::version::is_newer` parses dotted components and returns false for anything non-numeric — staying quiet beats nagging somebody toward a version they already have. It lives in `tmc-core` because the game installer asks the same question; do not grow a second copy.
- **`meets_minimum` is not `!is_newer(want, have)`.** That expression answers true when EITHER side is unorderable, which would wave through exactly the build that declared a `minClientVersion`. An unorderable requirement is refused; an unorderable own version passes, because a development build has no business being told it is too old.
